# ARM32 mlibc implementation plan

Goal: reusable ARM32 libc with explicit ISA, instruction state and FP ABI;
ChickenOS syscall/TLS/thread integration stays in sysdeps/chickenos/arm.

Approved design: common C/C++ and ABI definitions; capability-selected assembly.
Biscuit first uses ARMv7-A base AAPCS, followed by ARMv5TE/Thumb-1 coverage.
Hard-float and Thumb-only M-profile are not implied by the initial profile.

- [x] Execute setjmp/longjmp tests: zero becomes one, signed return values,
  r4-r11/SP preservation, ARM/Thumb interworking. Compile ARMv5TE and ARMv7-A
  caller modes; use ARM-state libc assembly that works on both A-profile ISAs.
- [x] Define shared jump-buffer layout, reserve VFP state consistently and
  distinguish ISA availability from soft/hard-float calling convention.
- [ ] Add machine ABI headers, compiler-runtime helpers, TLS and atomics with
  explicit fallback/admission for pre-v7 CPUs; never assume TPIDR or LDREX.
- [ ] Build static mlibc; add ChickenOS syscall/startup/thread/signal bindings,
  then boot a real static userspace program under ChickenOS in QEMU.
- [ ] Validate Thumb ELF entry, signals and syscall return in ChickenOS;
  ARM-only kernel validation currently rejects Thumb and must change explicitly.
- [x] Build static and shared libraries together; dynamic execution remains a separate acceptance gate.

Sources: ARM-software/abi-aa aapcs32, aaelf32, rtabi32, addenda32.
Implementation source base: fork rebase-2026-09 at 8241cce6, preserving the
existing ChickenOS/RISC-V32 work. No target hardware operation is involved.

Initial result: six QEMU executions pass, including ARM926 ARM/Thumb-1.
That initial slice has since advanced to the complete builds described below. See tests/arm32/README.md for exact coverage and exclusions.

## Dynamic support is required

Static is an intermediate checkpoint, not the final deliverable. The port must
build libc.so and ld.so and run shared-library startup, TLS, constructors,
symbol lookup/dlopen, and mixed ARM/Thumb calls. The ChickenOS cross-builder's
existing static-only restriction for bare-metal triples must be replaced by a
correct explicit shared-link driver configuration for the ARM32 profile.

The interpreter bootstrap now handles its own ARM REL records and preserves
instruction-state bits. Actual relocated ELF fixtures pass for ARM and Thumb,
including GOT/data/PLT references. A focused regression caught and corrected
an incorrect addend assumption for unresolved PLT slots. This does not yet
constitute a working complete dynamic linker or userspace libc.

The initial ChickenOS syscall assembly now passes actual user/SVC execution
checks for 0..6 words, wide r1:r0 results and TLS helper preservation in v5/v7
ARM/Thumb profiles. It uses only the established ChickenOS syscall numbers;
this does not implement the corresponding kernel dispatcher or TLS lifecycle.

Process startup objects crt1/crti/crtn execute in ARM/Thumb fixtures with
original-stack/main-pointer and init/fini alignment checks. The earlier missing
runtime.S build stop is superseded by the complete library integration below.

## Complete library integration

The ARMv7-A soft-float profile builds libc.a, libc.so and ld.so, in both ARM
and Thumb-2 C/C++ modes with ARM-state interworking assembly. This includes
ELF32 REL relocation definitions, eager PLT binding, nearest-only soft-float
fenv, compiler lock-free atomic admission, ChickenOS signal context and clone
entry glue. Shared-library linking selects Clang's ELF driver explicitly;
compilation and sysdeps remain ChickenOS, with no Linux runtime linkage.

Sixteen QEMU executions cover jump/fenv, relocated interpreter bootstrap,
user/SVC syscall and clone entry, CRT, and real compiler-generated TLS accesses.
The TLS regression uses aligned(32) and aligned(64) variables in ARM and Thumb
code, with two independent thread storage areas. It failed with the original
fixed-eight-byte layout and passes with linker-compatible padding. Late
initial-exec TLS cannot increase the alignment of existing thread pointers.

Real static and PIE clients and a Thumb shared object with dynamic TLS also
link against the staged libraries. Those full-libc clients have NOT executed:
full ChickenOS userspace startup, dlopen and thread lifecycle remain open.

Pre-v7 jump/syscall/CRT assembly is exercised, but full pre-v7 libc explicitly
refuses compilation until a kernel-assisted atomic fallback exists. Hardware
FP, hard-float, Thumb-only M-profile, lazy ARM PLT, TLSDESC and IFUNC are not
claimed. Kernel ARM32 syscall dispatch, thread-pointer switching, signal
return and Thumb admission still require integration and execution acceptance.
No physical target operation was performed for this work.
